## 5. Decisions and rationale

- The worker depends on a `JobRepository` protocol so Python remains the media-processing boundary and the typed application/database layer owns persistence decisions.
- The in-memory repository is explicitly not a production fallback. A later adapter must claim jobs transactionally in PostgreSQL and use lease ownership tokens.
- Cancellation is represented as terminal `failed` with code `cancelled` because the existing database enum only defines queued/processing/completed/failed. This avoids an unplanned schema fork.
- Timeout is cooperative. Handlers must checkpoint between bounded media subprocesses; individual FFmpeg calls must also have subprocess timeouts. Python cannot safely kill arbitrary in-process handler code from a thread.
- Temporary artifacts are always removed by the workspace context manager. Persistence promotion is intentionally not implemented until secure media intake/storage exists.
