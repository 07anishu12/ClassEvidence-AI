## 5. Decisions and rationale

- Prisma 6.19.3 is pinned instead of the currently exposed Prisma 8 release candidate to keep the foundation on a stable matching client/CLI pair.
- No real provider implementation was added because organiser approval is not documented. A blocked adapter is safer than a fake success path.
- The initial API stores only a validated source reference and creates a durable queued job when a database is available. It does not claim processing or a grade.
- The worker is intentionally limited to local metadata probing; semantic assessment and media extraction belong to later stages.
- Compose contains only the database service at this stage; adding app/worker container images before their runtime contracts exist would be misleading scaffolding.
